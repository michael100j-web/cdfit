# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Sessions started in this folder are often about unrelated work; this file matters only when the task touches CD Fit.

## What this is

CD Fit fits CD and UV melting curves of collagen model peptides (Tm, trimer ⇌ 3 monomers) and analyses CD spectra. One fitter lives in three places that must give the same numbers:

- **Word add-in**: `src/taskpane.html` is the whole app (data table, Prism-syntax equation compiler, Levenberg–Marquardt, SVG graph, Word integration). No build step. It is served from GitHub Pages: a push to `main` updates the live add-in for every user within about a minute.
- **Claude skill**: `skill/cdfit/` is a Python port. `scripts/cdfit_engine.py` follows `taskpane.html` line by line, including JavaScript's number formatting and rounding. `cdfit.py` is the CLI (`fit`, `list`, `compare`, `example`); `cdfit_word.py` writes and reads .docx files whose graph pictures carry the add-in's state in their alt text (`#CDFIT-STATE`), so the add-in can edit them; `cdfit_repr.py` holds optional representations (MRE/ε, off-peak reference, fraction folded) that are applied only when the person chooses one.
- **Artifact page**: `artifact/cdfit.html` is generated by `tools/build_artifact.py` from `taskpane.html` plus `artifact/src/*`. Never edit `cdfit.html` by hand.

Pairs that must change together: `taskpane.html` ↔ `cdfit_engine.py`; `artifact/src/import.js` ↔ `cdfit_files.py` (instrument readers: JASCO, Chirascan, spreadsheets); `artifact/src/spectra.js` ↔ `cdfit_spectra.py`.

## Rules

- After changing the add-in's fitting code: port it to `cdfit_engine.py`, set `ADDIN_VERSION` there to the new `APP_VERSION`, run `make_golden.py`, then the tests.
- A new add-in version bumps `APP_VERSION` in `src/taskpane.html` and `version` in `src/version.json` together (Word's self-update compares them).
- The repository is public: tests use only synthetic data (`skill/tests/fake_files.py`, `make_cases.py`). Never commit measured data.
- Skill scripts must parse under Python 3.8 (claude.ai's sandbox), and the SKILL.md description must stay ≤ 1024 characters without `<`; `test_cli.py` checks both.
- Skill work is on branch `claude-skill`; `main` is the live add-in.

## Commands (PowerShell or Bash, from the repo root)

```bash
py skill/tests/test_parity.py                    # Python port vs the add-in's own results (golden.json)
py skill/tests/test_cli.py                       # CLI, Word round trip, file formats, SKILL.md checks
py skill/tests/test_cli.py CLI.test_spectrum     # one test (or: py -m pytest skill/tests -k spectrum)
py skill/tests/make_golden.py                    # re-run the 16 cases through taskpane.html in headless Edge/Chrome
py tools/build_artifact.py --check               # rebuild the artifact page and check it reads the fake files to the same Tm
py tools/install_skill.py                        # copy the skill to ~/.claude/skills/cdfit and build dist/cdfit-skill.zip
py -m http.server 3000 -d src                    # preview the add-in at http://localhost:3000/taskpane.html
```

## Publishing

- Artifact page: republish `artifact/cdfit.html` with the Artifact tool (icon `chart`, capabilities `downloads` and `sample`).
- Lab-wide skill: `install_skill.py` updates only the local copy. The Fiala Lab MUNI copy changes when `dist/cdfit-skill.zip` is uploaded under claude.ai Organization settings → Plugins & skills → Add → Upload a skill.
